# MQTT 协议基础

> 来源：学习笔记，整理 MQTT 协议核心概念。

---

## 1. QoS 三个等级

| 等级 | 语义 | 说明 |
|------|------|------|
| QoS 0 | 最多一次 | 消息只发送一次，不确认，可能丢失 |
| QoS 1 | 最少一次 | 保证至少送达一次，可能重复 |
| QoS 2 | 恰好一次 | 严格保证恰好送达一次，无丢失无重复 |

---

## 2. 发布-订阅模型

与传统的客户端-服务器直连不同，MQTT 采用 **发布者 ↔ Broker ↔ 订阅者** 三层架构：

- **空间解耦**：发布者和订阅者无需知道对方地址
- **时间解耦**：发布者和订阅者无需同时在线（Broker 缓存）

```
发布者 ──publish──→  Broker  ──subscribe──→ 订阅者 A
                              ──subscribe──→ 订阅者 B
                              ──subscribe──→ 订阅者 C
```

---

## 3. 核心概念

| 概念 | 说明 |
|------|------|
| MQTT 客户端 | 运行 MQTT 客户端库的设备（传感器、控制器、App 等） |
| MQTT Broker | 消息代理服务器，负责接收、过滤、分发消息 |
| 主题（Topic） | 基于字符串的消息分类标签，如 `bess/station1/pcs/status` |

---

## 4. 特点

- **轻量级**：报文开销小（最小仅 2 字节头部），适合低带宽、低功耗设备
- **可靠性**：提供 3 级 QoS，按需选择
- **安全性**：支持 TLS/SSL 传输层加密
- **双向通信**：客户端既可发布也可订阅
- **多语言支持**：Python、C、Java、JS 等均有成熟客户端库

---

## 5. 储能/BESS 场景关联

- **云端监控**：站端 EMS 通过 MQTT 上送数据到云平台（比 Modbus TCP 更省带宽）
- **边缘网关**：嵌入式网关通过 MQTT 对接多个子设备
- **告警推送**：QoS 1/2 保证告警消息不丢失
- **局限**：BESS 核心实时控制仍以 Modbus/CAN/61850 为主，MQTT 更多用于信息化层
